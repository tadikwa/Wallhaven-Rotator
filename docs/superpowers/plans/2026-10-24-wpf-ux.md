# WPF responsiveness and lifecycle implementation plan

> Execute in this session with superpowers:executing-plans; verify each task before the next.

Goal: keep selection off the Dispatcher and keep every control/window reachable without changing wallpaper policy.
Base: fe614dd, branch fix/wpf-responsive-selection, draft PR stacked on PR #10.
Architecture: reuse existing engine functions inside one dedicated STA runspace. Only immutable settings/target input, cancellation token and progress queue cross the boundary; WPF stays on its Dispatcher. Reservations and API permits remain authoritative under their existing mutexes.

Constraints: PowerShell 5.1; 32:9/Strict/daily exclusions/history and API quotas unchanged; no installation, release, merge or user-data edits.

- [x] History: tests first for five unchanged 5000-entry reads with zero writes/normalizations, expired pending and one-time legacy migration. Measure real Stopwatch durations before/after. Cache one snapshot per selection; reservation still rechecks disk.
- [x] Worker: add Desktop helper functions and a dedicated runspace host; reuse canonical engine functions, own HTTP client and state. Coalesce manual clicks, cancel on settings change/exit, release reservation in finally, consume results only on Dispatcher. Test a real Dispatcher heartbeat while work is delayed and cancellation/concurrency/cleanup.
- [x] Layout: preserve all named controls; move option body into a right-hand cell, internal scroll, compact vertical fallback. Compute geometry from the actual HWND monitor work area and effective DPI; clamp physical window position after size/monitor/DPI changes. Test 5120x1440,1920x1080,1366x768 and 100/125/150/200% DPI, negative monitor coordinates and taskbar insets.
- [x] Lifecycle: load ICO into WPF, ensure ownerless APPWINDOW style when visible; close hides, tray restores/activates, exit waits for cooperative worker cleanup then disposes resources. Automated native HWND tests plus an isolated interactive WPF check if supported.
- [ ] Delivery: all PowerShell 5.1 suites, Go tests/vet/build, review, commit/push, draft stacked PR and CI; report actual timing and distinguish automated/interactive/unverified evidence.

Review focus: external Screensaver writes during selection; settings/exit during an in-flight selection; mutex contention; monitor/DPI changes; canceled or failed work must not leak reservations or refill API budgets.

Baseline measured locally (PowerShell 5.1, isolated fixture): five reads of 5000 entries -> five rewrites and five normalizations; median 308.9992 ms, maximum 386.1538 ms. The reported 6782 ms desktop selection is user evidence, not reproduced as a whole yet.

Execution ledger: all 13 PowerShell 5.1 suites, Go tests/vet/build pass locally. Reviewer found OTA bypassing worker cleanup; reproduced red then fixed green through Request-DesktopExit. Counter freshness and narrow 200% DPI viewport were pinned by additional failing tests and corrected. Interactive gate remains: real HWND exists but Computer Use inventory exposes no fixture window, so taskbar/Alt+Tab/tray visual claims are withheld. See tests/WpfUx-validation.md.

Resource probe after first push confirmed URI-loaded WPF icon locks the ICO. Added exclusive-file-open regression (red), fixed with OnLoad + disposed stream (green). Second validation cycle carries this focused follow-up; no more than three cycles authorized.
